# Analysis of `hessian_matrix` and `structure_tensor` `order` Equivalence

## User Prompt
Consider the function `hessian_matrix` in `main/src/skimage/feature/corner.py`. It has the keyword argument `order=` with default `rc`. `xy` is an alternative values for this argument. I am considering removing the `order=` argument, and only allowing `rc` behavior. However, I would like to give users the ability to reproduce the `xy` behavior, by post-processing the outputs of the `hessian_matrix` function, that has executed in `rc` mode. What is the simplest code that will allow that post-processing, so that I will get identical results from `hessian_matrix(image, order='xy')` and `some_postprocessing(hessian_matrix(image, order='rc'))`?

## Response
To exactly reproduce the behavior of `order='xy'` using only the `order='rc'` implementation, there are two approaches depending on whether you want "mathematical" equivalence or "numerical" identity.

### 1. The Simplest Code (Mathematical Equivalence)
For 2D images, `order='rc'` returns the Hessian elements in the order `[Hrr, Hrc, Hcc]` (where `r` is axis 0 and `c` is axis 1). `order='xy'` returns them in the order `[Hyy, Hxy, Hxx]` (where `y` is axis 0 and `x` is axis 1, matching the imaging convention).

Mathematically, $H_{rc} = H_{xy}$ and $H_{rr} = H_{yy}$ (if we assume $y$ is the vertical axis), but in scikit-image's `xy` convention, $x$ is axis 1 and $y$ is axis 0. Thus, `order='xy'` is exactly the reverse of `order='rc'`.

The simplest code for post-processing is:
```python
# Assuming H_rc = hessian_matrix(image, order='rc')
H_xy = H_rc[::-1]
```

### 2. The Numerical Identity (Exact Equivalence)
If you use `use_gaussian_derivatives=True` (which will be the default in future versions), the Hessian is not numerically symmetric ($H_{01} \neq H_{10}$) because of how boundary conditions are handled in successive 1D filter passes. In this case, `H_rc[::-1]` will differ slightly from the original `order='xy'` output.

To get **identical** results (to machine precision) for any mode or derivative type, you must transpose the image before the call and transpose the result elements back:

```python
# Exact reproduction of hessian_matrix(image, order='xy')
H_xy = [h.T for h in hessian_matrix(image.T, order='rc')]
```
*(Note: If `sigma` is non-isotropic, you must also swap its elements: `sigma=sigma[::-1]`)*.

## User Prompt
`hessian_matrix` accepts ND data. Your analysis appears to assume the data is 2D. How does your analysis change with ND data? Now consider the function `structure_tensor` in the same file as `hessian_matrix`. It also has an `order=` parameter, with the same meaning. Do the same analysis as you have just done for `hessian_matrix` on code to replicate the output of `order='xy'` using the output of `order='rc'`.

## Response
To replicate the `order='xy'` behavior for ND data using only the `order='rc'` implementation, you must account for the fact that the internal list of elements corresponds to the combinations of axes in a specific order.

For any dimension $N$, `order='xy'` is intended to represent the Hessian or structure tensor where the axis order is reversed compared to `rc`.

### The Simple Relationship (2D only)
In 2D, both `hessian_matrix` and `structure_tensor` yield a list of 3 elements.
- `rc` order: `[(0,0), (0,1), (1,1)]`
- `xy` order: `[(1,1), (1,0), (0,0)]`
Since $(0,1) = (1,0)$ (mathematically), `xy` is simply the reverse of `rc`:
```python
# 2D only
H_xy = H_rc[::-1]
```

### The ND Relationship (3D and higher)
For $N > 2$, the simple reversal `[::-1]` **fails**. This is because the sequence of pairs generated by `combinations_with_replacement` on a reversed list of axes is not the same as the reversed sequence of pairs on the original list.

For example, in 3D ($N=3$):
- `rc` order: `[(0,0), (0,1), (0,2), (1,1), (1,2), (2,2)]`
- `xy` order: `[(2,2), (2,1), (2,0), (1,1), (1,0), (0,0)]`
Reversing `rc` would give `[(2,2), (1,2), (1,1), (0,2), (0,1), (0,0)]`, which is incorrect (e.g., elements 1 and 4 are swapped).

### The Robust ND Solution (Numerical Identity)
The simplest and most robust way to reproduce `order='xy'` for **any** dimensionality $N$ and for **both** `hessian_matrix` and `structure_tensor` is to transpose the input image and transpose each result element back. This method also guarantees **numerical identity** to machine precision, bypassing the symmetry issues in `hessian_matrix` with Gaussian derivatives.

```python
def get_xy_from_rc(func, image, **kwargs):
    """Replicate order='xy' using order='rc' logic."""
    # Transpose image to reverse axes
    image_t = np.transpose(image, axes=range(image.ndim)[::-1])
    
    # Handle sigma if provided as a sequence
    if 'sigma' in kwargs and not np.isscalar(kwargs['sigma']):
        kwargs['sigma'] = kwargs['sigma'][::-1]
        
    # Call the 'rc' version
    res_rc = func(image_t, order='rc', **kwargs)
    
    # Transpose elements back
    return [np.transpose(h, axes=range(image.ndim)[::-1]) for h in res_rc]

# Usage
H_xy = get_xy_from_rc(hessian_matrix, image, sigma=1)
S_xy = get_xy_from_rc(structure_tensor, image, sigma=1)
```

### Summary for your Refactoring
If you remove the `order=` argument:
1.  **2D Users**: Can use `H[::-1]` for a quick fix (or the transpose method for numerical exactness).
2.  **ND Users**: Must use the transpose-reverse-transpose pattern shown above.
3.  **Note**: `structure_tensor` already restricts `order='xy'` to 2D only in the current codebase, but the transpose method would allow users to extend this "imaging convention" to 3D if they desire.
